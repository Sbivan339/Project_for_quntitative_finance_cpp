# Движок для бэктестинга торговых стратегий

[![CI](https://github.com/Sbivan339/Project_for_quntitative_finance_cpp/actions/workflows/ci.yml/badge.svg)](https://github.com/Sbivan339/Project_for_quntitative_finance_cpp/actions/workflows/ci.yml)

Движок на C++17 для проверки торговой стратегии на исторических данных. Реализована стратегия пересечения скользящих средних с учётом комиссий и исполнением сигнала на следующем ценовом шаге.

[Документация API](https://sbivan339.github.io/Project_for_quntitative_finance_cpp/)

## Возможности

- Загрузка исторических цен из CSV.
- Настраиваемые периоды быстрой и медленной скользящих средних.
- Учёт начального капитала и комиссии за каждую покупку и продажу.
- Расчёт итоговой стоимости портфеля, доходности и максимальной просадки.
- Сохранение истории сделок и стоимости портфеля через C++ API.
- Консольная программа для запуска бэктестинга.

## Требования

- Компилятор с поддержкой C++17: GCC, Clang или MSVC.
- CMake версии 3.20 или выше.
- Git.
- Doxygen — для локальной генерации документации.

При первой конфигурации CMake автоматически загружает GoogleTest и Google Benchmark. Для этого необходим доступ к GitHub.

## Сборка

```sh
git clone https://github.com/Sbivan339/Project_for_quntitative_finance_cpp.git
cd Project_for_quntitative_finance_cpp

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
```

Для сборки только консольной программы без тестов и бенчмарка:

```sh
cmake -S . -B build-core \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=OFF \
  -DBACKTEST_BUILD_BENCHMARKS=OFF

cmake --build build-core --parallel 2
```

При использовании Visual Studio добавьте `--config Release` к команде сборки и `-C Release` к команде CTest. Исполняемые файлы будут находиться в соответствующих подкаталогах `Release/`.

## Запуск

Запуск со встроенным примером:

```sh
./build/backtest_cli
```

Запуск с данными из файла:

```sh
./build/backtest_cli data/prices.csv
```

Программа выводит количество цен, итоговую стоимость портфеля, доходность, максимальную просадку и количество исполненных сделок.

Параметры по умолчанию:

| Параметр | Значение |
|---|---|
| Начальный капитал | 10 000 |
| Комиссия | 0,1% от объёма каждой сделки |
| Период быстрой средней | 3 |
| Период медленной средней | 5 |

Параметры стратегии можно изменить через структуру `backtest::Config` в C++ API.

## Формат данных

CSV-файл должен содержать один столбец с заголовком `close`:

```csv
close
100
101.5
99
102.3
```

Цены должны быть положительными и конечными. Десятичный разделитель — точка. Строки располагаются в хронологическом порядке. Лишние столбцы и некорректные значения вызывают ошибку.

## Модель исполнения

До заполнения медленного окна портфель остаётся в деньгах. Когда быстрая средняя выше медленной, стратегия запрашивает длинную позицию на весь доступный капитал. В остальных случаях целевая позиция — деньги.

Сигнал на шаге `i` исполняется по цене шага `i + 1`. Последний сигнал без следующей цены не исполняется. Допускается дробное количество единиц инструмента.

Комиссия списывается при каждой покупке и продаже. Открытая позиция в конце ряда оценивается по последней цене без принудительной продажи.

Доходность рассчитывается как:

```text
final_equity / initial_cash - 1
```

Максимальная просадка — наибольшее относительное снижение стоимости портфеля от достигнутого пика. Начальный капитал также учитывается при определении пика.

## Тестирование

Тесты используют GoogleTest и запускаются через CTest:

```sh
ctest --test-dir build --output-on-failure --no-tests=error
```

Проверяются исполнение сигналов, комиссии, расчёт доходности и просадки, обработка входных данных и отсутствие влияния будущих цен на прошлые сделки.

## Бенчмарк

Для измерения производительности используется Google Benchmark:

```sh
./build/benchmarks/backtest_benchmark \
  --benchmark_min_time=0.1s \
  --benchmark_repetitions=3
```

Измеряется время выполнения `backtest::run` на рядах из 1 000, 10 000 и 100 000 цен. Генерация входных данных выполняется вне измеряемого цикла.

Результаты содержат время выполнения в микросекундах и количество обработанных цен в секунду. Один прогон имеет временную сложность O(n).

## Документация

## CI/CD

GitHub Actions автоматически выполняет при каждом `push` и pull request:

- сборку проекта;
- запуск тестов;
- измерение производительности;
- генерацию документации.

После успешной проверки основной ветки документация публикуется на GitHub Pages.

Результаты бенчмарка доступны в журнале запуска и артефакте `benchmark-results`. Сгенерированная документация сохраняется в артефакте `doxygen-html`.

## Ограничения

Модель поддерживает один инструмент и длинные позиции. Не учитываются короткие продажи, проскальзывание, дивиденды и ограничения ликвидности. Цены рассматриваются как равноотстоящие наблюдения.
