# Назначение

Учебный C++17-проект: движок бэктестинга стратегии пересечения скользящих
средних. Один инструмент, long/cash, пропорциональные комиссии, исполнение
сигнала на следующем ценовом шаге.

# Структура

- `include/backtest/` — публичный API с комментариями Doxygen.
- `src/` — библиотека движка и CSV-парсер.
- `app/` — консольная программа.
- `tests/` — unit-тесты GoogleTest и регистрация CLI-тестов.
- `benchmarks/` — Google Benchmark.
- `data/` — небольшой демонстрационный ряд цен.
- `docs/` — главная страница документации и шаблон Doxygen.
- `.github/workflows/ci.yml` — сборка, тесты, замер скорости и публикация Pages.

# Команды из корня репозитория

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure --no-tests=error
./build/backtest_cli data/prices.csv
./build/benchmarks/backtest_benchmark --benchmark_min_time=0.1s
```

Документация, если установлен Doxygen:

```sh
cmake -S . -B build -DBACKTEST_BUILD_DOCS=ON
cmake --build build --target docs
```

# Правила и ограничения

- Перед завершением задачи собери проект и запусти тесты. Если проверку
  блокирует среда, явно укажи, что выполнено, а что проверить не удалось.
- При изменении расчётов добавляй тест на соответствующее поведение.
- Не меняй CI/CD, зависимости и модель исполнения без запроса пользователя.
- Не исполняй сигналы по уже известной цене того же шага: сохраняй задержку на шаг.
- Используй C++17, отступы 4 пробела и `.clang-format`.
- Имена типов — PascalCase, функций и переменных — snake_case.
- Публичный API документируй через Doxygen; ошибки входных данных — исключения.
- Не добавляй реальные ключи API, персональные данные и результаты сборки.
- Не используй `using namespace std` в заголовках и ручное управление памятью.
- Не выдавай непроверенный workflow или непубликованную документацию за работающие.
